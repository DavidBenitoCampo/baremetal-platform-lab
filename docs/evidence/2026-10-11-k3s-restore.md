## Flux recovery

The node and applications were running, but Flux reconciliation timed out.
The Git source and all four Kustomizations still reported commit `9ae8116e`.

The kustomize-controller logs included:

```text
failed to update status: timed out waiting for the condition
```

Stopping K3s leaves its containers running. The Flux controller Pods had
last restarted before the database restore.

I restarted source-controller and waited for its rollout:

```bash
kubectl rollout restart deployment/source-controller -n flux-system
kubectl rollout status deployment/source-controller -n flux-system --timeout=180s
```

The Git source then fetched commit `2b8224e807618a0a84752b2a57832248d0413722`.
Root Kustomization reconciliation still timed out. A Pod check showed
source-controller had a new Pod, while kustomize-controller still used its
original Pod.

I requested a restart of kustomize-controller and waited for its rollout:

```bash
kubectl rollout restart deployment/kustomize-controller -n flux-system
kubectl rollout status deployment/kustomize-controller -n flux-system --timeout=180s
```

Both controller rollouts completed. I requested reconciliation again:

```bash
flux reconcile source git flux-system -n flux-system
flux reconcile kustomization flux-system -n flux-system
flux get kustomizations -A
```

Observed final state:

| Kustomization | Applied revision | Suspended | Ready |
| --- | --- | --- | --- |
| flux-system | `main@sha1:2b8224e8` | False | True |
| monitoring | `main@sha1:2b8224e8` | False | True |
| ollama | `main@sha1:2b8224e8` | False | True |
| podinfo | `main@sha1:2b8224e8` | False | True |

The controller restarts resolved the observed reconciliation timeouts.
Stale controller state after restoring the older database is the leading
explanation. I did not inspect the controller caches to confirm the mechanism.

## Scope

This test restored K3s control-plane state.

The backup does not include Ollama model data, Prometheus history, Grafana data, application PVC data, the operating system, or the Pi hardware.

This was a restore on the same Pi with its existing SSD and application volumes.
The test does not demonstrate recovery from SSD loss or restoration of PVC data.
No recovery duration or recovery point measurement was recorded.
